# GASP integration — handoff brief

Goal: replace the player's **movement** animation (idle, walk, run, starts/stops, turns, jump, land, traversal) with
Epic's **Game Animation Sample (GASP)** motion matching, while **keeping** everything RPG-specific that already works:
unarmed combat, kicks, block, flight loops, first person, Power System, ragdolls. Combat/flight clips stay as they are
(procedural placeholders, user-approved) and play *over* GASP movement.

Written 2026-10-21 for whichever agent picks this up (Codex now, Claude later). Read this whole file first.

## Facts about this project (checked 2026-10-21)

- **Player** = `/Game/ThirdPerson/Blueprints/BP_ThirdPersonCharacter` (template Blueprint, CharacterMovementComponent).
  Game mode `BP_ThirdPersonGameMode`. C++ gameplay is added at runtime by `URPGControllerInputComponent::EnsureHelperComponents()`
  (`Source/RPG_CODEX/RPGControllerInputComponent.cpp`): combat state, movement abilities (flight), camera mode (first person),
  interaction, prototype animations, melee hits, strike contact, combat aim, stats, flight animation.
- **Skeleton:** everything of ours is on `/Game/Characters/Mannequins/Meshes/SK_Mannequin` (UE5 Manny).
  **GASP's animations are on `SK_UEFN_Mannequin`** (2,300+ files under `Characters/UEFN_Mannequin`). GASP drives Manny via retargeting.
- **Anim Blueprint:** `/Game/Characters/Mannequins/Anims/Unarmed/ABP_Unarmed`, reparented to C++ **`URPGAnimInstance`**
  (`RPGAnimInstance.h`). Its proxy runs after the graph and does: spine turn/tilt toward attack aim, the first-person
  upper-chest swing, and strike-contact IK. **Whatever ABP ends up on the player must keep `URPGAnimInstance` as its parent**
  (or this behaviour must be moved), otherwise aiming, first person and contact break.
- **Combat/flight clips** are `RPG_Proto_*` and `RPG_FP_*` in `/Game/RPG/Animations/Prototype`, generated by
  `Tools/ProtoAnim` (poses.py → protoanim.py → ue_import.py; see Docs/ANIMATIONS.md). They play as **dynamic montages in
  `DefaultSlot`** (`URPGPrototypeAnimationComponent`, `URPGFlightAnimationComponent`). The new ABP needs a `DefaultSlot`
  slot node near the end of its graph (after motion matching, before the output pose).
- **Flight** uses `MOVE_Flying`; GASP has no flight. While flying, our flight loops own the body (full-body slot).
- **First person:** `URPGCameraModeComponent` makes a shadow body copying the mesh's anim class (`SetAnimInstanceClass(Mesh->GetAnimClass())`).
- **Test dummy** (`RPGCombatTestDummy.cpp`) uses `SKM_Manny_Simple` + `BS_Idle_Walk_Run`; leave it alone in stage 1.
- **Tests:** run `Automation RunTests RPG` headless before/after each stage. Known failures that already exist: `DummyWander`,
  the first-person "Shadow setup" one-frame flake.

## Stages (stop and get user approval after each)

1. **Bring GASP in.** In the GameAnimationSample editor, migrate (right-click → Asset Actions → Migrate) the CMC character
   set into RPG_CODEX: `Blueprints/SandboxCharacter_CMC`, `SandboxCharacter_CMC_ABP`, their components (`AC_*`, `BPI_*`),
   and what the migrate dialog pulls in (UEFN mannequin animations, pose search databases, choosers). Use the **CMC** versions,
   not Mover — this project is built on CharacterMovementComponent. Enable the plugins GASP needs (Pose Search, Chooser,
   Motion Warping, Animation Warping, etc. — copy from GameAnimationSample's .uproject). Open the project, fix warnings,
   play GASP's character in a test level. Commit.
2. **Movement on our player.** Give `BP_ThirdPersonCharacter` GASP movement while keeping our components. Preferred: make
   the player's ABP the GASP one (Manny version / retarget setup), reparent it to `URPGAnimInstance`, add a `DefaultSlot`
   slot node near the end, and copy over the CMC settings GASP relies on (rotation, accelerations) without breaking our
   sprint/flight. Walk/run/jump should look like GASP. Commit.
3. **Combat + flight on top.** Check every attack, kick, block, charge and the flight loops still play and blend back into
   GASP movement. Film with `Visual.AttackShots` / `Visual.ClipShots`. Fix slot/blend problems. Run tests. Commit.
4. **First person.** Check the shadow body and FP clips (`RPG_FP_*`) with the new ABP; fix. Commit.
5. **Later (Claude, after usage reset):** teach `Tools/ProtoAnim` the UEFN skeleton (or retarget its output) if needed, re-take
   the fist/stance probes, re-film and get approval; update Docs/ANIMATIONS.md.
